One spec, five targets: the t27 backend shootout

2026-10-27 · 6 min read

[measured on arm64 Mac, warm cache, median of three runs] One spec — specs/t27os/heartbeat_monitor.t27, three tests, six pure functions — taken out five ways: t27b build to a 608 B arm64 object in ~1.0 ms (70-100x faster compile than clang, 28x smaller artifact), t27b test verdict in ~5.3 ms, and t27b verilog to ~311 lines RTL. Runtime sits within 2.4% of clang -O2; manual source unrolling was measured and made compilation slower.

#Compiler#Benchmark#t27b#arm64#Verilog

specs/t27os/heartbeat_monitor.t27 — the AEL v2.0 autonomous-loop monitor: liveness verdict, phase-wrap legality, and a frozen-tick budget of 3. Three tests, six pure functions, no strings (the t27b subset does not carry str methods).

One spec in, five ways out. The question: what does each backend cost, and what does each one buy?

Compile-time unrolling: measured receipt

t27b does not yet support a --unroll compiler flag. The following measures hand-unrolled .t27 source files, not compiler metaprogramming.

Manual source unrolling does not improve runtime throughput. It increases frontend work: parsing, typechecking, and codegen scale with source size. The next experiment must implement real compiler-level metaprogramming: a --unroll N path that expands a pure function at compile time, preserves semantics, and reports both logical and executed calls.

Major Achievements

  • Compile time advantage: t27b is 70-100x faster than clang
  • Size efficiency: t27b objects are 28x smaller than C binaries
  • Runtime performance: Within 2.4% of clang -O2 optimization
  • Test speed: 0.005ms execution time from 5.3ms JIT build
  • Compile-time metaprogramming: not yet implemented in t27b. t27b build rejects --unroll. Manual source unrolling was measured and made compilation slower; it is not a runtime optimization.

What This Enables

The AEL v2.0 autonomous loop now runs a real monitor, not a mock:

spec (.t27) --t27b test--> 5 ms verdict  (every tick)
          |
          +--t27b build--> 1 ms native .o    (deploy the watchdog)
          |
          +--t27c test--> reference verdict  (CI gate)
          |
          +--t27b watch--> rebuild + act on every spec change (live monitor)

t27b watch <spec> -o out.o --then '<cmd>' rebuilds on file change and fires <cmd> after every successful build — measured live: spec touched, REBUILT printed within a second. That is the heartbeat primitive.

What this does not settle

  • Every timing is a warm-cache median of three runs on one arm64 Mac; no cold-build, CI-machine or silicon figures are established.
  • The 70-100x compile, 28x size and runtime figures are measurements against the listed toolchain versions on that machine; they were not rerun for this publication.
  • Manual source unrolling was measured and made compilation slower; compiler-level --unroll is not implemented, so runtime Calls/s for unrolled specs is not measured.
  • The Python runtime figure is normalized from a 10M-call run (4.5 s), not a direct 200M-call measurement.
  • tri shootout improve and specs/tri/shootout/*.t27 are proposed contracts, not built commands.
