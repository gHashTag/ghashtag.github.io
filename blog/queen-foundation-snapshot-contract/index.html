The page contract is the useful part

[proven] The page reads the server route /queen/public-foundation first and the checked-in file second, refreshing the source every 60 seconds. The viewport exposes data-foundation="N@generatedAt:source", so a rendered view can say how many records it used and where they came from.

[measured] The new check:queen-foundation contract uses a 37-issue fixture. It checks the route response, accepts the route 404 as a wire-stage condition, and then requires the viewport to expose 37@<moment>:file. This tests provenance instead of treating a green page as proof that its data is current.

What is established

  • [measured] PR #937 is merged and its public diff adds the foundation snapshot, the source contract, and the page wiring.
  • [proven] The snapshot has a timestamp and explicit counts, while the page reports source and record count through data-foundation.
  • [proven] The repository adds an automated foundation contract rather than relying on a screenshot or an unlabelled number.

What is not established

  • The server route is not established as live by this merge; the contract explicitly tolerates its current 404 while the checked-in file remains the fallback.
  • A dated repository snapshot is not proof that the underlying GitHub ledger is complete, current, or independently verified.
