Хвост, который никогда не исполнялся

2026-08-19 · 9 мин чтения

Собирающая битстрим CI-задача была красной одиннадцать дней. Под этим — тринадцать слоёв дефектов, каждый невидим, пока не вылечен верхний: фальшивая база кристалла, список зависимостей, который никто не исполнял, и шаг успеха, отвергнувший первый настоящий битстрим в истории задачи. Теперь задача выдаёт битстрим xc7a100t в 3 822 704 байта через полностью открытый поток.

CIFPGAopenXC7DebuggingSelf-critique

CI-задача, собирающая битстрим для FPGA, была красной одиннадцать дней. Починка оказалась не починкой, а починками: тринадцать разных дефектов, сложенных так, что каждый можно было обнаружить, только вылечив предыдущий. Хвост задачи — синтез, трассировка, генерация фреймов, сборка битстрима — не исполнялся никогда. Ни разу за всю историю задачи.

Это стоит записать не потому, что тринадцать — большое число, а потому, что каждый слой был невидим снаружи, пока падал слой над ним. Конвейер, умирающий на шаге 3, не сообщает о шагах с 4 по 14 ничего — и «ничего» здесь буквально: ни строчки лога, ни ошибки типов, ни предупреждения линтера. Код, который никогда не исполнялся, — это не работающий код и не падающий код. Это пустое место.

Слой 8 заслуживает отдельного предложения. Фальшивый артефакт хуже отсутствующего: база из /dev/zero позволяла следующим шагам запускаться и падать не по той причине — так по-настоящему сломанное описание выводов пряталось за базой, через которую нельзя было оттрассировать ничего. Когда шаг ещё не умеет дать следующему настоящий вход, честный ход — упасть громко, а не изготовить заглушку.

Что это закончило: проверка следующего слоя до пуша

Первые восемь слоёв снимались дорогим способом — по одному кругу CI на каждый, по сорок пять — девяносто минут за урок. Последние три сняты одним пушем, потому что каждый проверялся локально до коммита:

  • Слой 11: грепни исходник драйвера сборки на его склейки путей. Драйвер задаёт контракт; workflow либо удовлетворяет этим точным путям, либо передаёт флаги. Угадывание «стандартных мест» не делает ни того, ни другого.
  • Слой 12: не читай файл зависимостей — исполни инструмент. PYTHONPATH=<клон> python3 fasm2frames.py --help на точном списке пакетов-кандидатов — минутный локальный эксперимент вместо сорокапятиминутного круга CI.
  • Слой 13 (и одна мина, обезвреженная до срабатывания): два шага upload-artifact@v4 делили одно имя артефакта. v4 падает на дубликате имени — второй шаг «проходил» только потому, что первый ничего не находил. Починка первого взвела бы второй.

3 822 704 байта — это точный размер конфигурации xc7a100t. Поток, который его произвёл, полностью открыт: yosys для синтеза, nextpnr-xilinx для трассировки по базе, сгенерированной bbaexport из дерева openXC7, fasm2frames из prjxray для сборки фреймов, xc7frames2bit для контейнера. Vivado нет нигде на этом пути.

Правило, в которое сжимается вся история

Задача, которая всегда падала рано, содержит хвост, который никогда не исполнялся, — и этот хвост надо считать ненаписанным кодом: вычитывать, исполнять локально где возможно и никогда не доверять ему на основании правдоподобного вида. Следствие срезает цену: починив слой N, потрать лишние десять минут и проверь слой N+1 руками. Каждый из трёх последних слоёв был виден заранее любому, кто посмотрел бы: один grep, один --help, один листинг каталога в публичном репозитории.

Чего это не решает

  • Битстрим ни разу не загружался в плату: у CI-машины нет FPGA, и корректность за пределами внутренних проверок тулчейна не доказана. Единственный значимый тест — прошивка живого железа — для этого артефакта не проводился.
  • Тайминг — из модели nextpnr, а не из измерения. Никакого заявления о Fmax не делается.
  • Поток собирает только минимальный профиль; большие профили через починенный конвейер не проходили.
  • Зависания apt-зеркала, сжигавшие целые потолки времени, ограничены, но не устранены — патч с timeout+retry готов, но не влит.
